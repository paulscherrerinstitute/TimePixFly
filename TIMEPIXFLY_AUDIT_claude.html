Summary

The hot path is sound. Everything around it is not.

tpx3app is a capable, performance-focused backend — lock-free ring buffers, AVX2 decode paths, CPU pinning, jemalloc — written essentially by one author (385 of 395 commits). That architecture holds up. The risk sits in the control plane, error handling, lifecycle transitions and the output stage: code written for the happy path and never hardened against aborts, restarts, a second client, or a dead consumer — which is exactly the regime of a beamline running back-to-back scans.

Single-slot shared state, no ownership discipline

The WebSocket state channel is one static unique_ptr shared by every handler thread and read without its mutex — the root of 8 findings across 3 independent auditors, up to use-after-free. The same one-global-slot, last-writer-wins pattern recurs in the Redis publisher cache and the raw-data listener.

Errors are dropped, not propagated

TcpWriter never checks stream state, so a dead consumer silently discards every frame while the scan reports success. EndFrame failures are swallowed. The except state is overwritten by config within microseconds. There is no metrics or health endpoint. A scan can lose 100 % of its data with every observable signal reporting success.

One error poisons every later scan

Latched signals and caches are never reset — stop_sig permanently kills the state stream after any restart, writer_finished desyncs the writer handshake forever, reconnect() omits disconnect(), stop_handlers accumulates dangling references. The failure mode is silent degradation requiring a process restart, matching the incidents already seen in integration testing.

Why these survived. The reason is structural, not individual: there is no automated test of the output path. All six Julia scripts in test_data/ validate the raw input stream; not one parses StartFrame/XesData/EndFrame, and src/test.cpp is wired into no CI. The five worst data-integrity defects all live in precisely that untested region.

Proven by execution

TPX-058 — TOA timestamps computed in 32-bit arithmetic

The one finding proven by running code rather than reading it. In src/include/decoder.h:208-213, spidr is a 16-bit bit-field, so C++ integral promotion evaluates the shift in 32-bit signed arithmetic:

inline static u64 getToaClock(TOA event) noexcept
{
    // ftoa is on a 640 MHz clock
    // toa is on a 40 MHz clock
    return ((event.spidr << 18) + (event.ToA << 4)) - event.FToA;
}

Compiling that struct and expression verbatim under the project's own production flags (-O3 -ffast-math -DNDEBUG):

decltype(e.spidr << 18) is int? YES -> 32-bit arithmetic (sizeof=4)
spidr=40000: buggy=1895827008  correct=10485761600  *** MISMATCH ***
  spidr= 8191 (t= 3.355s into cycle): buggy=          2147221504  correct=          2147221504  ok
  spidr= 8192 (t= 3.355s into cycle): buggy=18446744071562067968  correct=          2147483648  BROKEN
  spidr=20000 (t= 8.192s into cycle): buggy=           947912704  correct=          5242880000  BROKEN
  spidr=65535 (t=26.843s into cycle): buggy=18446744073709289472  correct=         17179607040  BROKEN

Timestamps are correct only while spidr < 8192 — the first 3.36 s of every 26.84 s SPIDR cycle, 12.5 % of the time. For the other 87.5 % the shift overflows int, sign-extends into u64, and yields garbage. No crash, no error, plausible-looking histograms.

That the scalar path is the defect and not the intent is settled by the AVX path, which computes the same quantity correctly in 64 bits — src/include/avx2_decoder.h:53:

const auto spidr = _mm256_slli_epi64(_mm256_and_si256(events, spidr_mask), 18);

_mm256_slli_epi64 is a 64-bit shift, so the two decode paths disagree. compile.sh:32-38 leaves the AVX flags empty unless USE_AVX is set, making the scalar path the default, and both container images build with GENERIC=1 ./compile.sh — so the shipped images carry the defect.

One-line fix 
return ((u64{event.spidr} << 18) + (u64{event.ToA} << 4)) - u64{event.FToA};

Then sweep sibling bit-field expressions for the same promotion trap and add -fsanitize=undefined to CI — UBSan names this immediately.

This compounds with TPX-059: even once the arithmetic is fixed, the TOA clock wraps at 234 ticks (26.8 s) and the TDC clock at 236 (107.4 s), with no wraparound handling anywhere — any acquisition that straddles a wrap produces underflowed relative times.

TPX-002high Concurrency & pipelineconcurrency
